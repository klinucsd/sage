# ARGUS — Science Agent for Jupyter Notebooks

**ARGUS** (Science Agent) is a natural language data science agent for Jupyter notebooks. Unlike general-purpose AI assistants that return text answers, ARGUS delivers **complete, verified scientific results** — interactive maps, charts, structured tables, and a narrative summary — all rendered inline in a notebook cell. Every intermediate script, data file, and API call is saved and inspectable, making results fully reproducible and shareable.

> *You ask a scientific question. ARGUS answers it with data.*

ARGUS is developed as part of the [National Data Platform](https://nationaldataplatform.org) (NDP) project, supported by the NSF. It is built on top of [deepagents-code](https://pypi.org/project/deepagents-code/).

---

## Why ARGUS?

| | General AI Assistant (e.g. ChatGPT) | ARGUS |
|---|---|---|
| **Input** | Text | Text |
| **Output** | Text | Interactive maps, charts, tables, narrative |
| **Data sources** | None (knowledge cutoff) | Live APIs, catalogs, spatial services |
| **Verification** | Not possible — no sources | All scripts and intermediate data saved and inspectable |
| **Reproducibility** | Not reproducible | Re-run the notebook, get the same result |
| **Shareability** | Share a chat link | Share a `.ipynb` file — prompts, tool calls, outputs all included |
| **Domain extension** | Not possible | Add a skill file |

## Features

### 1. Natural Language Requests
Ask scientific questions in plain English using the `%%ask` cell magic. No programming required.

```
%%ask
Find earthquakes of magnitude > 5 in the United States between Dec 3–15, 2024,
and show them on a map with magnitude and location details.
```

### 2. End-to-End Result Delivery with Self-Correction
ARGUS does not generate code and hand it back to you — it runs the full analytical pipeline autonomously: data discovery, retrieval, code generation, execution, and verification. When a step fails (API error, schema mismatch, unexpected null values), the agent diagnoses the failure, revises its approach, and retries — without any user intervention. The final output is a verified result, not a code draft.

### 3. Rich, Structured Output
Every `%%ask` response delivers:
- **Interactive maps** — GeoJSON and WMS layers combined on a single Folium map with layer controls
- **Charts** — PNG figures rendered inline
- **Tables** — CSV results rendered as pandas DataFrames
- **Narrative summary** — natural language explanation of findings, embedded with visualizations where most relevant

### 4. Full Transparency and Verifiability
Every tool call — API request, code execution, file read — is displayed as a collapsible panel inside the notebook cell, before the narrative continues. All generated scripts and intermediate data files are saved to a dedicated output folder (`_{notebook_name}_sage_/`) next to the notebook. Nothing is hidden. Any result can be verified by inspecting the exact code and data that produced it.

### 5. Reproducible and Shareable Workflows
A ARGUS notebook is a self-contained scientific record: the natural language prompts that drove the analysis, the complete tool-call trace at every step, and all rendered outputs — captured automatically in a standard `.ipynb` file. Sharing the notebook shares the entire analytical workflow. Re-running it reproduces the results.

### 6. Cross-Cell Conversational Memory
ARGUS maintains conversational context across cells. Each cell builds on the findings of the previous ones without re-stating context. A second cell can refer to "the earthquake from the previous cell" and ARGUS resolves it from memory — enabling coherent multi-step scientific reasoning within a single notebook session. Use `%reset` to start a fresh session.

### 7. Extensible Skill Architecture
ARGUS's domain knowledge is supplied through **skills** — plain-text `SKILL.md` files that describe data sources, APIs, and analytical workflows. Skills can be **written by hand** by any domain scientist (no coding required), **generated by the agent** from an API description, or **installed at runtime** from any of these sources:

- **Local paths** — paths to skill directories on the user's filesystem
- **GitHub URLs** — `github.com/<org>/<repo>/tree/<commit>/...` references
- **[SkillsMP marketplace](https://skillsmp.com)** — curated catalog of community skills

Use the **`%%skill` cell magic** to install from local paths or GitHub URLs:

```
%%skill
github.com/klinucsd/sage_skills/tree/main/wildfire/sdge-goes-fire
/home/jovyan/private_skills/my-custom-skill
# blank lines and comments are ignored
```

**This makes ARGUS notebooks fully self-contained for sharing.** A notebook declares the skills it needs in `%%skill` cells; when a collaborator or reviewer opens the notebook and runs it, the required skills install automatically into their kernel. No separate "install these dependencies first" instructions, no environment drift between authors and readers — the notebook itself is the complete specification of what to run. Skills from allowlisted GitHub organizations install silently; skills from unknown organizations surface a single trust prompt with `SKILL.md` descriptions for review before any code is loaded.

The marketplace path is also accessible from a regular `%%ask` cell (e.g., *"install the hurricane response skill"*), without restarting the kernel. Adding a skill extends ARGUS to a new scientific domain without modifying any core code.

### 8. MCP (Model Context Protocol) Integration
ARGUS connects to any [MCP](https://modelcontextprotocol.io)-compliant server with the `%%mcp` cell magic, exposing the server's tools to subsequent `%%ask` cells. Accepts the same JSON config used by Claude Desktop / VS Code / Gemini — no ARGUS-specific format:

```
%%mcp
{
  "mcpServers": {
    "wenokn": {"url": "https://wenokn.fastmcp.app/mcp"}
  }
}
```

Multiple `%%mcp` cells **merge** (per-server replace on name collision), so different cells can register different servers and the combined toolset stays available. Use `$VARNAME` interpolation in any string field for authentication tokens. See [`examples/clm_mcp.ipynb`](examples/clm_mcp.ipynb) for a working demo against the California Landscape Metrics MCP server.

### 9. Self-Improvement via Learnings.md
ARGUS keeps a per-skill `Learnings.md` file in the workspace. When a `%%ask` cell hits a subtle data quirk, a working-but-non-obvious approach, or an avoidable failure, the agent can record the lesson into the relevant skill's `Learnings.md`. Subsequent cells in the same workspace pick up those learnings automatically, so ARGUS gets better at your specific domain over time without changing any code. Learnings are local to your workspace — they don't leak to other users — and you can edit or delete them like any other Markdown file.

### 10. Multiple LLM Providers
ARGUS works with any LangChain-compatible LLM endpoint. Configure your preferred provider in a `config.toml` file:

| Provider | Notes |
|---|---|
| NRP GLM-5 | Free for NRP/NDP users; default in the published image (GLM-4.7 available as a fallback) |
| OpenAI GPT-5.5 | Standard OpenAI API |
| Anthropic Claude | Via `langchain_anthropic` |
| Any OpenAI-compatible endpoint | `base_url` configurable |

## Quick Start — Run Locally with Docker

### Prerequisites
- [Docker](https://docs.docker.com/get-docker/) installed
- An API key for a supported LLM provider

### 1. Create a workspace folder

```bash
mkdir ~/sage-workspace && cd ~/sage-workspace
```

### 2. Add your API key

```bash
# .env
NRP_API_KEY=your_nrp_key_here
# OPENAI_API_KEY=sk-...
# ANTHROPIC_API_KEY=sk-ant-...
```

### 3. Add your LLM configuration

```toml
# config.toml — OpenAI example
[models]
default = "openai:gpt-5.5"

[models.providers.openai]
class_path = "langchain_openai:ChatOpenAI"
models = ["gpt-5.5"]
api_key_env = "OPENAI_API_KEY"
base_url = "https://api.openai.com/v1"

[models.providers.openai.params]
temperature = 0
```

```toml
# config.toml — NRP GLM example
[models]
default = "nrp:glm-5"

[models.providers.nrp]
class_path = "langchain_openai:ChatOpenAI"
models = ["glm-5", "glm-4.7"]
api_key_env = "NRP_API_KEY"
base_url = "https://ellm.nrp-nautilus.io/v1"

[models.providers.nrp.params]
temperature = 0
stream_chunk_timeout = 1200.0   # NRP GLM occasionally pauses mid-stream; raise from the 120s default
max_retries = 6                 # auto-retry transient connection errors with exponential backoff
```

### 4. Start ARGUS

```bash
docker run -p 8888:8888 \
  -v ~/sage-workspace:/home/jovyan/work \
  kaiucsd/sage-dev:v1.4.0 \
  jupyter lab --ip=0.0.0.0 --NotebookApp.token=''
```

### 5. Open JupyterLab

Open **http://localhost:8888** in your browser. Copy your `config.toml` into the container once:

```python
import shutil, os
shutil.copy("/home/jovyan/work/config.toml", os.path.expanduser("~/.deepagents/config.toml"))
```

## Using ARGUS

### Magic commands

```python
# Single-line prompt
%ask find earthquake events with magnitude > 5 near California in 2024

# Multi-line prompt (required when the prompt contains '?')
%%ask
What GNSS stations are within 100 miles of the M5.7 Parker Butte earthquake
on December 9, 2024? Report the distance from the earthquake to each station.
```

### Session commands

```python
%reset    # Clear output files, conversation history, and execution log — start fresh
```

### Output folder

All generated files (scripts, GeoJSON, CSV, PNG) are saved to `_{notebook_name}_sage_/` next to the notebook. This folder persists across kernel restarts and is cleared by `%reset`.

```markdown

```
